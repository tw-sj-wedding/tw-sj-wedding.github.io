# 엔드리스 스노보드 미니게임 설계

> 2026-10-14 · 결정 기록: `docs/DECISIONS.md` (#26~)
> 이 문서는 `HANDOFF.md`와 `2026-09-12-stage1-and-entry-design.md`를 **대체한다.**
> 두 문서에서 살아남는 것은 §3 타깃 환경 제약과 §8 리더보드 보안 항목뿐이며, 필요한 부분은 이 문서에 옮겨 적었다.

## 1. 목표

크롬 공룡 게임 같은 **엔드리스 러너를 스노보드로** 만든다. 하객이 청첩장 최상단 카드로 들어와
신랑 또는 신부를 골라 설원을 달리고, 부딪히면 끝나며, 원하면 점수를 하객 리더보드에 올린다.

- 이야기 구간·스테이지 구분 없음. 게임은 하나다.
- 경품 없음. 리더보드는 재미용이고 검증은 기본 수준이다.

## 2. 범위 밖

리플레이 검증(서버 재시뮬), 사운드(소리 없이 성립해야 하며 `audio.js`는 unlock 배관만 유지),
야간 모드, 길게 눌러 높이 뛰기, 공중 급강하, 이야기 연출, 경품.

## 3. 타깃 환경 (하드 제약, HANDOFF §3에서 이관)

- 주 경로는 **카카오톡 인앱 브라우저** (Android WebView / iOS WKWebView), 세로 전용, 터치. 성능 기준은 보급형 갤럭시.
- 높이는 `100dvh` / `window.innerHeight` 기준 (`100vh` 금지). 노치는 `env(safe-area-inset-*)`.
- 게임 영역: `touch-action: none; overscroll-behavior: none; user-select: none; -webkit-touch-callout: none;`. 더블탭 확대 방지.
- Fullscreen API·화면 방향 고정 사용 안 함.
- iOS 엣지 스와이프, Android 뒤로가기, 앱 전환(`visibilitychange`, `pagehide`) → 일시정지.
- 오디오는 첫 탭에서 unlock하고, 무음 모드에서도 게임이 성립해야 한다.
- 카톡 인앱 캐시가 강하므로 **해시 파일명 번들이 유일한 무효화 수단**이다. 배포 전 빌드는 필수.

## 4. 화면 구성

```
┌──────────────────────────┐  ← safe-area
│ ⏸           HI 01240  00342 │  HUD (HTML)
│   ▲▲  먼 산                 │  배경 2겹 패럴랙스
│ ▲▲▲▲▲  가까운 언덕            │
│        🐦                  │  ┐
│  🏂            🪨   ⛄      │  │ 게임 띠
│══════════════════════════│  ┘ 지면선
│  ┌─────────┐ ┌─────────┐ │
│  │ ⬇ 숙이기  │ │ ⬆ 점프   │ │  조작 버튼 (HTML)
│  └─────────┘ └─────────┘ │
└──────────────────────────┘
```

**해상도와 배율**
- 논리 가로 **400**. 세로는 화면 비율에 맞춰 늘어난다 (대략 700~900).
- **보이는 가로는 기기와 무관하게 400 고정** (구현 중 변경, DECISIONS #34). 내부 해상도는
  `400 × k` (`k = ceil(물리폭 / 400)`, 정수)로 그리고 CSS 로 화면 폭에 맞춰 약간 줄인다.
  `image-rendering: pixelated`. 처음 안(정수 배율 + 보이는 폭 360~430)은 DPR 1.5 기기에서
  보이는 폭이 540까지 벌어져 버렸다.

**배치**
- 캐릭터는 x = 60에 고정, 세계가 오른쪽에서 왼쪽으로 흐른다.
- 지면선은 화면 세로 중앙보다 약간 아래. 지면선 아래는 눈밭 배경 위에 조작 버튼 두 개.
- **슬로프 기울기**: 그릴 때만 하늘·먼 산(#52)을 뺀 언덕·눈밭·장애물·캐릭터를 신랑 발밑 기준 시계 방향 10°로 기울여 오른쪽 아래로 내려가는 내리막처럼 보인다 (#47). 시뮬·충돌·점수는 수평 그대로. 낮은 화면은 조작 버튼을 아래로 붙여 내려간 오른쪽 경사면을 가리지 않게.
- HUD(점수·HI·일시정지)와 버튼·메뉴는 HTML 오버레이로 선명하게 그린다.

## 5. 조작

- 지면선 아래 **버튼 두 개**: **왼쪽 = 숙이기, 오른쪽 = 점프**. 각 폭 약 45%, 높이 약 110 CSS px.
- 버튼은 `pointerdown`에서 즉시 반응한다. 눌린 동안 눌린 모양으로 표시한다.
- **숙이기**: 누르고 있는 동안 유지. 공중에서 누르면 아무 일도 없고, 누른 채로 착지하면 그때부터 숙인다.
- **점프**: 지상에서만 발동. 숙인 상태에서 누르면 점프가 우선한다. 두 버튼 동시 입력(멀티터치)을 받는다.
- 게임 화면(캔버스) 탭은 무반응.
- 첫 판에만 버튼 위에 "탭: 점프 / 누르기: 숙이기" 안내.
- 개발용 키보드: ↑ / Space = 점프, ↓ = 숙이기.

## 6. 화면 흐름

- **타이틀**: 신랑·신부 캐릭터 카드 두 장 — 고르면 즉시 시작. "리더보드 보기", "청첩장으로 돌아가기".
  마지막으로 고른 캐릭터를 강조 표시한다.
- **플레이**: HUD + 조작 버튼.
- **일시정지**: 앱 전환·뒤로가기·⏸ 버튼. "계속하기"를 누르면 3·2·1 카운트 후 재개.
  Android 뒤로가기는 `history.pushState`로 한 번 삼켜 이탈 대신 일시정지가 되게 한다.
- **게임오버**: 넘어짐 프레임 + 점수 + HI(갱신 시 표시). "다시 하기"(같은 캐릭터 즉시 재시작),
  "리더보드에 등록", "캐릭터 바꾸기", "청첩장으로".
- **하단 TOP 5** (리더보드 연결 시): 타이틀·게임오버에서 지면선 아래에 순위 1~5위를 늘 보여 준다.
  머리글 "전체 보기"를 누르면 순위표 패널. 게임 중·일시정지·등록 화면에서는 숨긴다 (DECISIONS #49).
- 게임 → 청첩장 복귀는 `../`. ~~카톡 UA면 "외부 브라우저로 열기" 보조 링크~~ — 제거 (DECISIONS #49).

## 7. 게임 규칙

모든 수치는 `game/src/config.js` 한 곳에 두고 실기기 체감 후 조정한다. 아래는 초기값이다.

**틱과 난수**
- 고정 60Hz 틱 + accumulator, 한 프레임 최대 5틱 따라잡기. 렌더는 틱 사이 보간.
- 판마다 새 seed, 시뮬 RNG는 mulberry32. 시뮬 모듈은 DOM·`Date`·`Math.random`을 쓰지 않는다
  (테스트 봇 재현용. 서버 재시뮬은 하지 않으므로 정수 고정소수점 규칙은 두지 않는다).

**속도와 점수**
- 출발 240 px/s, 매초 +3 px/s, **상한 없음** (1분 420, 2분 600, 3분 780 px/s). DECISIONS #47.
- 점수 = `floor(이동 거리 / 24)`. 100점마다 HUD 숫자 깜빡임. 5자리 표시.
- **한 번 부딪히면 게임오버.** 목숨 없음.

**점프·숙이기 (그림 실측 기준)**
- 점프: 정점 약 56 px(리프트 판정 윗면 60 px 보다 낮게 — #43), 체공 약 0.6초, 높이 고정.
- 충돌 상자(그림보다 작게, 억울한 판정 방지): 서 있음 20×48, 숙임 20×34, 발 기준 하단 정렬.
- 숙인 그림의 머리 꼭대기는 지면에서 약 43 px → 리프트(머리 높이 장애물)의 밑면을 **46 px**에 둔다.

**장애물**

| 종류 | 위치 | 피하는 법 | 등장 |
|---|---|---|---|
| 바위 | 지상, 작음, 1~3개 묶음 | 점프 | 처음부터 |
| 눈사람 | 지상, 큼 | 점프 | 처음부터 |
| 넘어진 스키어 | 지상, 낮고 넓음 (충돌 34×14, 그림 2종 40×19·37×27) | 점프 | 처음부터 |
| 리프트 의자·곤돌라 (머리 높이) | 머리 위 줄에 매달림, 밑면 46 px | 숙이기 | 150점부터, 장애물의 40% (#50, 처음 #47 은 10% — 낮은 새는 없앰) |

**공정성**
- 장애물 사이 최소 간격 = `현재 속도 × (체공 시간 + 반응 여유 0.25초)` 이상.
  간격은 이 최소값 위에서 RNG로 벌린다.
- 장애물은 논리 x = 460(화면 밖)에서 생성된다 (DECISIONS #35).

**기록**
- 최고기록(HI), 마지막 캐릭터, 닉네임, 익명 `playerId`(UUID)를 localStorage에 저장.
  모든 접근은 try/catch — 인앱에서 막혀도 게임은 동작한다.

## 8. 그림

**원칙: 그림은 손으로 고치지 않는다.** 어색하면 Gemini에서 다시 뽑는다.
코드의 책임은 받은 그림을 그대로 게임에 넣는 변환 도구까지다.

**캐릭터 원본**
- `game/assets/src/groom.png`, `game/assets/src/bride.png` — Gemini 생성, 마젠타(#FF00FF) 배경,
  가로 한 줄에 `달리기1, 달리기2, 점프, 숙이기1, 숙이기2, 넘어짐` 6프레임, 오른쪽 진행.
- 실측: 픽셀 한 칸 = 원본 3.75 px, 서 있는 키 약 55 px, 보드 폭 약 41 px, 점프 프레임 높이 약 64 px.
- 체크무늬 배경 버전(초기 생성본)은 쓰지 않으므로 삭제한다.

**변환 도구 `scripts/build-sprites.mjs`** (Node 표준 라이브러리만, zlib으로 PNG 직접 디코드·인코드)
1. **격자 검출**: 경계 위치의 주기를 측정해 칸 크기·위상을 찾는다.
2. **원본 해상도 복원**: 칸마다 대표색. 칸의 절반 이상이 마젠타면 투명. 분홍 번짐 픽셀은 이웃 색으로 대체.
3. **색 정리**: 근접 색을 묶어 32색 이하.
4. **프레임 분리**: 연결 성분으로 덩어리를 찾고, 작은 덩어리(워터마크)는 버린다. 6개가 아니면 진단을 출력하고 실패.
5. **64×64 정렬**: 보드 밑면을 맨 아래 줄에, 좌우 가운데. 64를 넘으면 실패.
6. **출력**: `game/assets/sprites.png` (6열 × 캐릭터 2행 = 384×128), `game/assets/sprites.json` (프레임 사각형),
   4배 확대 미리보기 (저장소 밖, 확인용).
- 칸 크기가 기준(3.75 ± 0.1)과 다르면 경고 — 같은 화면에서 픽셀 밀도가 달라 보이기 때문.

**게임에서**
- 달리기·숙이기 2프레임을 8틱마다 교대. 점프 중 점프 프레임, 게임오버 시 넘어짐 프레임.
- 시트 로드 실패 시 예외 없이 코드로 그린 임시 도형으로 진행.
- 충돌 상자는 그림과 독립 (`config.js`가 진실). 그림을 바꿔도 난이도가 흔들리지 않는다.

**장애물·배경**
- 나중에 같은 방식으로 Gemini 생성 (캐릭터 시트를 첨부해 "같은 스타일·같은 픽셀 크기·마젠타 배경").
  필요 목록: 바위 1~3개 묶음, 눈사람, 넘어진 스키어, 날개 2프레임 새. 같은 도구로 변환한다.
- 그 전까지는 코드로 그린 임시 도형. 배경(산·언덕·눈밭)은 코드로 그린다.

## 9. 리더보드

**구성**: Cloudflare Workers + D1 (무료 플랜), 코드는 `worker/`. 시크릿은 `wrangler secret`으로만.
Cloudflare 계정은 사용자가 생성한다. 착수 시 공식 문서로 무료 한도를 재확인한다.
선택 이유: Supabase 무료 플랜은 약 7일 무접속 시 프로젝트가 정지되어, 청첩장 배포 후 한산한 기간에 조용히 죽는다.

**흐름**
1. 판 시작 시 `POST /api/session`으로 토큰 발급. 실패해도 게임은 진행, 그 판만 등록 버튼 비활성.
2. 게임오버 → "리더보드에 등록" → 닉네임 입력(이전 닉네임 미리 채움) → 전송 → 순위표에서 내 순위 강조.
3. 타이틀 "리더보드 보기" → 상위 20명 + 내 순위. 닉네임 옆에 캐릭터 아이콘(신랑/신부).
4. 네트워크·서버 오류 시 등록 실패만 안내하고 게임은 계속.

**API**
- `POST /api/session` → `{ token }`. token = HMAC-SHA256(`issuedAt | nonce`). DB 쓰기 없음. 유효 3시간
  (판 시작 전에 미리 받아 두므로, DECISIONS #37). nonce 는 모든 검증을 통과한 뒤에만 소모 (#38).
- `POST /api/score` body `{ token, playerId, nickname, score, durationTicks, character, clientVersion }` → `{ rank, best }`.
  `playerId`당 최고 기록 1개 — 기존보다 낮으면 저장하지 않고 기존 기록과 순위를 돌려준다.
- `GET /api/leaderboard?playerId=` → `{ top: [{ rank, nickname, score, character }], me: { rank, score } | null }`.
  `top`은 Cache API로 30초 캐시.
- CORS 허용 오리진: `https://tw-sj-wedding.github.io` (개발 시 localhost 추가).
- 관리용 공개 엔드포인트 없음. 삭제·수정은 `wrangler d1 execute`로만.

**기본 검증**
- 서명·만료 확인, nonce 1회성 (`used_nonces`).
- `durationTicks / 60 ≤ (now − issuedAt) + 5초`.
- `score ≤ maxScore(durationTicks)` — 속도 곡선을 적분한 이론 최대치 (클라이언트와 같은 수식을 공유 모듈로).
- `clientVersion` 허용 목록, body 크기 제한, IP당 분당 10회 (IP는 salt 해시로만, 원문 저장 안 함).

**스키마 (초안)**
```sql
CREATE TABLE scores (
  player_id      TEXT PRIMARY KEY,
  nickname       TEXT NOT NULL,
  score          INTEGER NOT NULL,
  character      TEXT NOT NULL,      -- 'groom' | 'bride'
  duration_ticks INTEGER NOT NULL,
  client_version TEXT,
  created_at     INTEGER NOT NULL,
  updated_at     INTEGER NOT NULL
);
CREATE INDEX idx_scores_rank ON scores (score DESC, updated_at ASC);
CREATE TABLE used_nonces (nonce TEXT PRIMARY KEY, used_at INTEGER NOT NULL);
```

**닉네임·개인정보**
- 2~10자, 한글·영문·숫자, NFC 정규화, 서버측 욕설 필터, 예약어 차단(신랑·신부·태웅·수진·관리자·admin 등).
- 사용자 문자열 출력은 `textContent`만. SQL은 prepared statement만.
- 수집: 닉네임, 익명 playerId, 점수, 캐릭터. 실명·연락처 요구 금지.
- 기록은 지우지 않는다 — 등록 화면에 삭제 안내를 두지 않는다 (DECISIONS #64).

## 10. 코드 구조

1차 시도(`feat/stage1-minigame`의 `4e63d84`까지)에서 실기기용 뼈대를 재활용하고 게임 규칙은 새로 쓴다.

```
game/dev.html                 개발 진입점 (ES module 직접 로드)        재작성 (레이아웃·버튼)
game/index.html               릴리즈 진입점, 해시 번들만 참조 (생성됨)  신규
game/src/main.js              루프·상태 머신                          재작성 (루프 구조 재활용)
game/src/config.js            튜닝 수치·버전                          재작성
```

## 11. 테스트

`npm test` (`node --test "tests/**/*.test.mjs"` — 디렉터리 인자 금지, Node 24 제약).

- **시뮬 단위**: 점프 궤적(정점·체공), 공중 점프 무시, 공중 숙이기 무시·착지 후 숙임, 숙임 시 리프트 통과,
  서 있으면·점프해도 리프트에 충돌, 지상 장애물 충돌, 속도 곡선·상한, 점수 공식, 150점 전 리프트 미등장.
- **공정성**: 봇(가장 가까운 장애물 종류에 맞춰 점프/숙이기)으로 seed 300개 × 최대 5분 실행 →
  **피할 수 없는 배치 0건**. 최소 간격 공식이 지켜지는지 생성 단계에서도 검사.
- **결정론**: 같은 seed + 같은 입력 → 같은 점수·종료 틱.
- **변환 도구**: 작은 합성 이미지(칸 크기 4, 마젠타 배경, 덩어리 2개)로 격자 검출·투명 처리·프레임 분리·정렬 검증.
  실제 원본 2장에 대해 프레임 6개·각 64 이하·칸 크기 3.75 ± 0.1 검사.
- **점수 상한**: `maxScore(t)`가 봇 최고 점수보다 항상 크거나 같음.
- **Worker** (2부): 토큰 서명·만료·재사용, 시간 검증, 점수 상한, 닉네임 규칙, 낮은 점수 무시. curl로 조작 점수 거부 실측.
- 렌더·입력·레이아웃은 자동 테스트하지 않고 실기기로 확인한다.

## 12. 구현 순서와 완료 기준

**1부 — 게임 본체** (계획 문서 1)
1. 1차 코드 정리(폐기분 삭제), 그림 변환 도구, 스프라이트 생성

완료 기준:
- `npm test` 전부 통과.
- 로컬에서 청첩장 → 게임 → 게임오버 → 다시 하기 → 청첩장 왕복.
